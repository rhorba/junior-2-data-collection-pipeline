## Setup Development Environment

### Prerequisites

- Java 17
- Maven
- Docker and Docker Compose
- Git
- IDE (IntelliJ IDEA, Eclipse, or VS Code)

### Initial Setup

1. Clone the repository:
   ```bash
   git clone https://github.com/your-username/data-pipeline.git
   cd data-pipeline
   ```

2. Import the project into your IDE:
   - For IntelliJ IDEA: File > Open > Select the project directory
   - For Eclipse: File > Import > Existing Maven Projects > Select the project directory
   - For VS Code: Open folder and install Java extensions

3. Set up the environment variables:
   - Create a `.env` file with your OpenWeatherMap API key
   - Configure IDE run configurations to include environment variables

## Development Workflow

### 1. Create a Feature Branch

```bash
git checkout -b feature/your-feature-name
```

### 2. Implement Changes

Follow these principles when developing:

- **Maintain separation of concerns**: Keep different components in their respective packages
- **Follow SOLID principles**: Single responsibility, Open-closed, Liskov substitution, Interface segregation, Dependency inversion
- **Write clean code**: Use meaningful names, keep methods small and focused
- **Document your code**: Add Javadoc comments for public methods

### 3. Test Your Changes

- Run unit tests: `mvn test`
- Run the application locally: `mvn spring-boot:run`
- Test with Docker Compose: 
  ```bash
  mvn clean package -DskipTests
  docker-compose up -d
  ```

### 4. Commit and Push

```bash
git add .
git commit -m "Add your descriptive commit message"
git push origin feature/your-feature-name
```

### 5. Create a Pull Request

- Create a PR from your feature branch to the main branch
- Include a description of your changes
- Reference any related issues

## Adding New Features

### Adding a New Data Source

1. Create a new API client in the `client` package
2. Add configuration properties in `application.properties`
3. Create domain models for raw and processed data
4. Implement a data processing service for the new data type
5. Add Kafka producers and consumers
6. Update the GraphQL schema and resolver

### Adding a New API Endpoint

1. Create or modify a controller in the `controller` package
2. Implement the business logic in a service
3. Test the endpoint with tools like Postman or cURL

### Adding a New GraphQL Query

1. Update the GraphQL schema in `src/main/resources/graphql/schema.graphqls`
2. Add a new query method in the resolver
3. Implement any required repository methods

## Testing

### Unit Testing

Write unit tests for individual components:

```java
@SpringBootTest
class WeatherDataRepositoryTest {
    @Autowired
    private WeatherDataRepository repository;
    
    @Test
    void testFindByCity() {
        // Test implementation
    }
}
```

### Integration Testing

Test integration between components:

```java
@SpringBootTest
class KafkaIntegrationTest {
    @Autowired
    private RawDataProducer producer;
    
    @Autowired
    private WeatherDataRepository repository;
    
    @Test
    void testEndToEndFlow() {
        // Test implementation
    }
}
```

### API Testing

Test GraphQL API:

```java
@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT)
class GraphQLApiTest {
    @Autowired
    private GraphQlTester graphQlTester;
    
    @Test
    void testWeatherDataByCity() {
        // Test implementation
    }
}
```

## Deployment

### Local Deployment with Docker Compose

```bash
mvn clean package -DskipTests
docker-compose up -d
```

### AWS Deployment with Terraform

1. Update Terraform configuration if needed:
   ```bash
   cd terraform
   terraform plan
   terraform apply
   ```

2. Push changes to GitHub to trigger the CI/CD pipeline:
   ```bash
   git push origin main
   ```

3. Monitor the GitHub Actions workflow to ensure successful deployment

### Monitoring Deployed Application

- Check application health: `http://<app-url>/actuator/health`
- Monitor logs in CloudWatch
- Set up alerts for critical metrics

## Troubleshooting

### Common Issues

1. **Kafka connection issues**:
   - Check Kafka bootstrap servers configuration
   - Verify Kafka topics exist
   - Check security groups and network settings

2. **Database connection issues**:
   - Verify database credentials
   - Check database endpoint
   - Ensure database is running and accessible

3. **API connectivity**:
   - Verify API key is valid
   - Check network connectivity
   - Test API endpoint directly

4. **ECS deployment issues**:
   - Check ECS task definition
   - Verify IAM roles and permissions
   - Inspect container logs in CloudWatch
